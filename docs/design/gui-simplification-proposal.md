# Kusamushiri GUI 簡素化の設計案

状態: 承認・実装済み (2026-11-10)。Phase 1+2 は `718fc73`、相対期間は後続コミット。
対象: `src/kusamushiri/gui.py` のレイアウトのみ。core / CLI は触らない
(相対期間の保存のため `settings.py` に項目を2つ追加した)。

## 承認時に追加された要望: 相対期間

「今から○日以上前」の指定も欲しい、という追加要望があり、併せて実装した。
CLI の `--older-than` / レシピの `older_than_days` と全く同じ数え方
(ちょうど N 日前の日は含まず、上限は today − (N+1) 日。絶対指定の until と
併用した場合は早い方) を GUI の期間欄にチェック+日数で置き、プロファイルごとに
保存する。レシピの `older_than_days` は、読み込み時に日付へ焼き込まず、
この相対指定として読み込む (収集日に確定する) よう改めた。

## なぜごちゃごちゃして見えるか

機能が多いからではなく、**使用頻度が違うものが同じ優先度で並んでいる**からだ。

- 設定タブは3カラムに6グループ (基本設定 / 絞り込み条件 / プレビューと削除実行 /
  フォローの整理 / 読み込み・保存先 / 待機・通信方式)、投稿一覧タブにも
  診断・運用設定とログが常駐する。
- 毎回使うのは「プロファイルを選ぶ → ログイン → 条件を決めて収集 → 一覧で確認 →
  削除」だけ。その本線の周りに、プロファイルの改名・削除、メニュー診断、
  再試行の数値9項目、通信方式の方式名コンボなどが全て常時表示で並ぶ。
- タブが2つあるため、収集条件と結果が別画面に分かれ、収集のたびに画面が切り替わる。

## 原則

1. **機能は削らない。置き場所だけ変える。** CLI / レシピ (TOML) との対応も維持する。
2. **頻度で3層**: 本線は常時表示、たまに使う条件は折りたたみ、運用系はダイアログへ。
3. **1画面で本線が完結する**: タブをやめ、左レール (条件) + 右ワークスペース (一覧)
   の単一画面に戻す。元々の `docs/design/gui-design.md` のコンセプト (左レール +
   右テーブル) と同じ形で、今のタブ構成のほうが後からの逸脱だ。
4. **危険操作の分離は維持する**: 削除ボタンは一覧側の実行バーに置き、
   「削除/解除を有効にする」と間隔は実行の近くに残す。隠しすぎない。
5. **設定の保存形式 (QSettings のキー) と文言 (i18n) は流用する**。
   既存プロファイルの設定がそのまま効くことを、移行コストゼロの条件にする。

## 配置マップ (現行 → 提案)

### 第1層: 常時表示 (左レール + 実行バー)

| コントロール | 現行 | 提案 |
|---|---|---|
| プロファイル選択 | 基本設定 | レール最上部に残す |
| X アカウントID | 基本設定 | 残す |
| ブラウザ起動＆ログイン / ログイン状態 | 基本設定 | 残す (状態表示を1行に圧縮) |
| 収集モード (プロフィール走査 / 高度な検索) | 基本設定 | 絞り込みの先頭へ移動 |
| メディア条件 / 対象種別 | 絞り込み条件 | 残す |
| 期間 (この日以降 / この日以前) | 絞り込み条件 | 残す (チェック+日付を1行に) |
| 取得上限件数 | 絞り込み条件 | 残す |
| ポストを収集＆プレビュー | 設定タブ下部 | レールの絞り込み末尾 (主ボタン) |
| フィルタ要約 | 投稿一覧タブ | 一覧の上部に残す |
| 投稿テーブル / 選択件数 / すべて選択 | 投稿一覧タブ | 右ワークスペースに残す |
| チェック項目を保存 | プレビューと削除実行 | 実行バーへ |
| 削除/解除を有効にする + 間隔 | プレビューと削除実行 | 実行バーの削除ボタン近くに残す (安全装置は見える場所) |
| チェック項目を削除/解除 | フッター | 実行バー右端 (danger) |
| ブラウザ停止 / 処理中止 | フッター | 実行バーに残す |
| ステータス / 進捗バー | フッター | 最下部に残す |
| TOML設定を読み込む / 使い方 / 言語 | ヘッダー・フッター | ヘッダー右の小ボタン群に集約 |

### 第2層: 折りたたみ「詳細条件」(レール内、既定は閉)

| コントロール | 現行 |
|---|---|
| 含むキーワード / 除外キーワード | 絞り込み条件 |
| 最低いいね数 / 最低返信数 | 絞り込み条件 |
| リプライのみ | 絞り込み条件 |
| 自動保存間隔 (秒) | 絞り込み条件 |
| X のアーカイブから読み込み + パス + 古い順 | 基本設定 / 読み込み・保存先 |
| 一覧の保存先フォルダ | 読み込み・保存先 |

閉じているときも、**設定されている項目があれば要約を1行出す** (例: 「詳細条件: 除外『固定』、最低いいね 10」)。
畳んだことで条件に気付けない事故を防ぐためで、既存のフィルタ要約の仕組みを流用する。

### 第3層: 「運用設定」ダイアログ (ヘッダーのボタンから開く)

| コントロール | 現行 |
|---|---|
| 待機・再試行設定の数値9項目 | プレビューと削除実行 (設定タブ3カラム目) |
| 待機・通信方式 (待機上限の方式 / 補助通信の制限方式 / 通信ポリシー / ランダム追加待機) | 待機・通信方式 (設定タブ2カラム目) |
| 診断・運用設定 (表示中の投稿URL / メニューを診断 / 表示中のこの1投稿を削除) | 設定タブ3カラム目 |
| プロファイル追加 / 名前変更 / プロファイル削除 | 基本設定 → プロファイル選択横の「管理」ボタンから同じダイアログへ |
| フォローを整理 / フォローリストをエクスポート | フォローの整理 |

### ログ

投稿一覧の下に常駐させず、**下端の折りたたみドロワー**にする (開閉状態は現行の
collapsible log の設計を流用)。普段はステータス1行で足りる。

## 実装の段階 (承認されたら)

1. **Phase 1: 再配置だけ**。単一画面化 + 詳細条件の折りたたみ + ログのドロワー化。
   ロジック・シグナル接続・設定キーは不変。`test_gui.py` の構造依存を更新する。
2. **Phase 2: 運用設定ダイアログ化**。再試行・通信方式・診断・プロファイル管理・
   フォロー整理を移す。ダイアログ側に新規テストを追加する。
3. **Phase 3: 仕上げ**。余白とグルーピングの最終調整、スクリーンショットで
   現行と比較して確認する。

各 Phase で全テスト + 実機起動確認までを1単位とし、Phase ごとにコミットを分ける。

## 判断が要る点 (推奨は明記)

1. **タブ廃止でいいか** — 推奨は廃止 (単一画面)。収集→確認の往復が消えるのが
   一番の効果。残す案だと簡素化の効果は半分になる。
2. **削除の有効化チェックの置き場** — 推奨は実行バーに残す。安全装置を
   ダイアログに隠すのは逆効果だと考える。
3. **フォロー整理の独立性** — 推奨はダイアログ。ただしポスト削除とは別の
   作業だと考えれば、ヘッダーに独立ボタンを残す案もある。
